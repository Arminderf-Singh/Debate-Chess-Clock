# DebateClock

## Product Purpose
A chess-clock-style debate timer for tracking speaking time across 2–6 debaters (1v1, 2v2, 3v3, 1v3 formats). Used by debate coaches, students, and tournament officials to enforce speaking time limits, detect simultaneous speech (overlaps), and log interruptions. The primary interface is a set of large, glanceable timer cards — one per speaker — that toggle on tap.

## Users
Debate coaches, tournament moderators, high school and college debate students. Used on-device (laptop or tablet) at a table or podium, often in a lit room with other people present. The moderator glances at the screen between speakers; the timers need to read instantly from 2–3 feet away.

## Register
product

## Brand
Precision instrument. The aesthetic should feel like a referee's stopwatch or a broadcast timer — authoritative, functional, zero decoration for decoration's sake. No tech-startup softness. No gamification. Time is the product; everything else is scaffolding.

## Tone
Direct. No onboarding fluff. Labels are short. Numbers are big. States are obvious.

## Anti-references
- GitHub dark UI (generic dark-blue dev tool aesthetic)
- SaaS dashboards with gradient hero metrics
- Sports-app scoreboard neon
- Material Design cards with drop shadows as personality

## Color
Warm amber as the single "live/running" signal — it reads "time is moving" without requiring color literacy. Team Affirmative: blue. Team Negative: rose-red. Background: very dark warm-tinted neutral, not pure black.

## Strategic principles
1. The timer digits are always the largest element on each card.
2. One tap starts a speaker; one tap stops them. No confirmation dialogs for normal actions.
3. Chess-clock behavior by default: starting one speaker stops all others.
4. Interruption logging is a secondary feature — visible but not dominant.
5. The control panel is a sidebar, not a modal. Settings should never obscure the clocks.
